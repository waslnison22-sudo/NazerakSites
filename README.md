# NaZerak — официальный сайт

Официальный статический сайт проекта NaZerak.

## Актуальные данные

- Minecraft: **1.21.11**
- IP сервера: **nazehard.rustix.cc**
- Официальный Discord: https://discord.gg/2KvsYYDHN6

## Структура

- `index.html` — главная страница
- `styles.css` — оформление, адаптивность и motion
- `script.js` — меню, анимации и копирование IP
- `scripts/qa-checks.mjs` — статические проверки перед публикацией
- `favicon.svg` — иконка сайта
- `supabase-loader.js` — отказоустойчивый загрузчик Supabase JS с резервным CDN
- `404.html` — страница ошибки
- `.nojekyll` — отключение Jekyll-обработки

Публичная часть сайта не требует npm или сборщика при работе. npm используется только в GitHub Actions для production browser smoke-тестов. Единственная внешняя runtime-зависимость кабинета — Supabase JS, загружаемый с фиксированной версией и резервным CDN.

## Проверка перед релизом

Без npm и без зависимостей:

```bash
node scripts/qa-checks.mjs
```

Скрипт проверяет структуру HTML, дубликаты ID, синтаксис JavaScript, целостность CSS, секреты, OAuth-контур и обязательные RLS-защиты.

## Локальный запуск

Для локального HTTP-запуска:

```bash
python -m http.server 8000
```

После этого открыть `http://localhost:8000`.

## GitHub Pages

Сайт рассчитан на публикацию **напрямую из ветки `main`**, без серверной сборки и без отдельного веб-сервера.

В GitHub открыть:

**Settings → Pages → Build and deployment → Source → Deploy from a branch**

Затем:

**Branch: `main` / Folder: `/(root)`**

После сохранения GitHub Pages будет раздавать содержимое репозитория.

## Принципы

Сайт должен оставаться быстрым и простым для хостинга:

- публичная часть остаётся статической и не требует собственного VPS;
- backend/БД нужны только для авторизации и функций личного кабинета;
- Node.js на сервере не требуется;
- без тяжёлых UI-фреймворков;
- реальные данные проекта добавляются только после подтверждения;
- анимации должны уважать `prefers-reduced-motion`.


## Discord авторизация и личный кабинет

В репозитории уже находятся:
- `cabinet.html` — личный кабинет;
- `auth.js` — Discord OAuth, сессия, профиль и заявки;
- `auth-config.js` — публичная конфигурация Supabase;
- `supabase/schema.sql` — таблицы и RLS;
- `supabase/migrations/` — дополнительные миграции безопасности;
- `AUTH_SETUP.md` — пошаговая настройка Discord + Supabase;
- `docs/account-architecture.md` — устройство кабинета, безопасность и план очереди модерации.

Для настоящего входа используется существующий Supabase project NaZerak. Нужно включить Discord Provider и задать корректные OAuth URL; публичный publishable key находится в `auth-config.js`, а Discord Client Secret и Supabase service_role в GitHub не попадают.


## Форум

Форум использует Discord как источник личности: Supabase Auth связывает Discord-аккаунт с внутренним user id, а публичный форумный профиль использует отдельный public_id, поэтому внутренние идентификаторы не попадают в ссылки и публичные выборки.

Основные поверхности:
- `forum.html` — каталог разделов, поиск, фильтрация и создание тем;
- `topic.html` — отдельная тема и ответы;
- `forum-user.html` — полноэкранный публичный профиль;
- `forum-ui.js` — компактные hover-карточки пользователей и роли;
- `forum.js` / `topic.js` / `user.js` — клиентская логика форума.

Стартовые разделы: новости и объявления, правила и документы, проект и развитие, игровой мир, государство и организации, помощь, идеи и предложения, жалобы и обращения, свободное общение.

Роли отделены от разрешений. Визуальные роли имеют собственные цвета и бейджи; административные permissions выдаются только через серверную таблицу forum_user_roles. Администратор проекта hell_nlrp привязан к своему Discord Auth-профилю и имеет permissions модерации/управления, а обычный пользователь автоматически получает роль Игрок.
